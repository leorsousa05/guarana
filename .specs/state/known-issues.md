## 2026-10-23 — Portuguese informational requests can be classified as orchestrator tasks
- **Symptom:** Portuguese informational questions containing a later mutation verb can be classified as `new_task`, causing an unwanted workflow transition and potentially downstream specs/vault bootstrap instead of remaining read-only.
- **Reproduction trigger and confirmed evidence:** Independent direct probes against both `orchestrator/decide.js` and `cli/orchestrator/decide.js` returned `new_task` for “Qual é a melhor forma de corrigir o login?” and “Por quê devo implementar PKCE?”. The existing Portuguese read-only examples pass but omit these interrogative forms. The CLI mirror is in sync with core, so the behavior reproduces in both. Bootstrap is a downstream risk of this classification; no bootstrap side effect is claimed from these classifier probes.
- **Root cause:** `hasMutationIntent` finds `corrigir`/`implementar` via `NEW_TASK_RE`, but neither phrase matches the direct, polite, or compound mutation forms. The final fallback at `orchestrator/decide.js` (`return !READ_ONLY_PREFIX_RE.test(text)`) therefore depends on the read-only prefix. That prefix misses singular `qual` (its existing `quais?` alternative does not match `qual`) and accented `por quê` (it recognizes unaccented `por que` only), so the fallback treats each question as mutation intent. The same code is present in the CLI mirror.
- **Mitigation:** Extend only the start-anchored Portuguese read-only prefix to recognize `qual`/`quais` and both `por que`/`por quê` (for example, replace the malformed `quais?` alternative with `qual|quais` and use `por\s+qu[eê]`). Keep explicit direct/polite/compound mutation checks ahead of the read-only fallback and preserve explicit `guarana:<skill>` handling ahead of automatic classification. Synchronize the CLI mirror. Add core and CLI regressions for the two exact informational forms, asserting no event/state change both from idle and during an active workflow; add plugin coverage asserting no bootstrap on either request. In the same suites, retain positive assertions for explicit Portuguese and English mutations and `guarana:<skill>` forcing.
- **Accepted mitigation and broader acceptance:** The TASKED follow-up in `.specs/features/orchestrator/orchestrator.md` also requires `goal`/`activeTask` to remain untrusted data separated from authoritative rules; workflow-event provenance limited to `source`, `sessionID`, and `agent` without user/tool content; and shared cross-session resume plus native Task identity behavior to remain intact. Core, plugin, and CLI regression tests are required.
