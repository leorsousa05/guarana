# Feature spec: Dashboard Memory Map pan-zoom and inspector redesign

**Status: VALIDATED**

## Goal
Redesign Memory Map navigation and node inspection: remove map scrolling, enlarge the visible map, and make selecting and understanding specific memories intuitive while preserving its visual style.

## Requirements
- Keep the Memory Index/Map toggle and make Memory Map the initial Memory display; keep the Index sidebar absent in Map mode.
- Make the map stage visibly larger on desktop and mobile. The graph stage is a non-scrolling pan/zoom surface with no visible scrollbars in either axis; below-map management controls may remain in ordinary document flow, and the page must not gain horizontal overflow.
- Provide named zoom-in, zoom-out, Fit map, and Focus selected controls, plus mouse-wheel zoom. Fit map bounds all visible graph nodes; selecting a node automatically focuses and centers it. Dragging empty/background canvas pans, while interacting with a node selects it and never moves it. Respect reduced motion.
- Keep deterministic automatic node positions. Do not add node dragging, saved coordinates, session/local storage reads, writes, or deletes.
- Make the selected node unambiguous and expose readable names for it and its direct neighbors through on-map labels and/or focus/hover disclosure. Place a contextual selected-memory inspector beside the map on desktop and stack it with the map on mobile; show scope, type, ID, title, summary, and typed incoming/outgoing relationships.
- Keep selection and inspector/map state synchronized when selection comes from the map, Memory Index, or relationship rows. Preserve existing relationship editor behavior and project/global privacy rules.
- Preserve Network as the default graph mode and retain Neighborhood, filters, scope-qualified IDs, keyboard roving focus and Enter/Space selection, actual directed edges, and empty/fallback states.
- Retain the existing visual language: bubble/type colors, scope rings, paper #F5F0E4, ink #1e1710, Guarana/critical #9E1B1E, leaf #3E5C3A, amber #B87A14, global #006b68, Space Grotesk display, IBM Plex Mono metadata, rule-led surfaces, and visible focus. Add concise discoverable gesture instructions.
- Make no API, backend, payload, vault schema/data, privacy, telemetry, external dependency/model, or new server capability changes.
- Use ADR-005 default budgets: main thread at most 8k steady-state tokens; worker-code 8k, worker-verify 4k, and worker-debug 6k tokens per dispatch; per-run hard cap 32k tokens and 15 minutes.

## Assumptions and scope
- The accepted desktop layout places the contextual selected-memory inspector beside the broad map stage; mobile stacks the map and inspector. Only the graph stage is non-scrolling.
- The existing Memory Map/Index behavior, Network/Neighborhood modes, filters, selection, data, and relationship semantics remain the baseline except that the old contained-map-scrolling allowance is superseded by the explicit no-map-scrolling choice.
- The validated .specs/features/dashboard/memory-graph-visualization.md and .specs/features/dashboard/memory-map-hide-index-sidebar.md records, including their historical status and proof, remain unchanged; the inspector is contextual and is not an Index/navigation sidebar.
- This is reversible UI/navigation behavior without API or data-contract changes; no ADR is warranted.
- Implementation has not begun as part of this planning record. No dated Changes receipt is created before validation, and no shipping claim is made.
- Browser checks use synthetic fixtures only. Preserve unrelated local changes, including unrelated existing Activity/Overview changes in dashboard/web/src/style.css.
- Dashboard Memory Map presentation and interaction in dashboard/web/src/components/MemoryGraph.jsx and dashboard/web/src/style.css.
- Deterministic graph layout behavior in dashboard/web/src/lib/memoryBubbleLayout.js and focused tests in dashboard/web/src/lib/memoryBubbleLayout.test.js.
- Memory component and selection regression tests in dashboard/web/src/components/Memory.test.mjs; use dashboard/server/routes/memory.js only as existing browser API fixture context, with no endpoint or contract change.
- Focused layout/component tests, full npm test, dashboard build and CLI sync, npm run check-cli, specs validation, git diff check, and browser verification at 1440px and 375px.

## Acceptance criteria
1. At 1440px and 375px, the map viewport is visibly larger than the current map, has no scrolling or visible scrollbars in either axis, and no behavior depends on scrollLeft or scrollTop. The page has no horizontal overflow. Memory Map remains the default display and no Index sidebar is present in Map mode.
2. Zoom-in, zoom-out, Fit map, and Focus selected controls are named and operable. Mouse-wheel zoom works; background dragging pans; node interaction selects without moving a node. Fit map includes all visible graph nodes, selecting a node recenters focus, automatic node positions remain deterministic, and no storage operation is added. Camera motion respects reduced-motion settings.
3. The selected bubble is unambiguous; selected and direct-neighbor names are readable on-map or through focus/hover disclosure. The nearby inspector immediately presents node identity, scope, type, ID, title, summary, and typed incoming/outgoing relationship meaning. Selection via map, Index, and relationship rows synchronizes map and inspector; existing relation editing and project/global privacy rules remain intact.
4. The Memory Index/Map toggle, default Map display, Network default, Neighborhood mode, filters, scope-qualified IDs, arrow-key roving focus, Enter/Space selection, actual directed edges, empty/fallback states, and absence of an Index sidebar in Map mode remain intact. No API/backend/payload/vault-schema/data/privacy change occurs.
5. Focused layout/component tests, full npm test, dashboard build and CLI sync, npm run check-cli, specs validation, and git diff check pass. Synthetic-fixture browser checks at 1440px and 375px verify viewport bounds and no scrollbars, enlargement, zoom/fit/focus controls, wheel zoom, background pan, immovable nodes, selection focus/labels/inspector/typed relationship meaning, Index switching, state preservation, keyboard/focus, no page overflow, and no browser errors. No shipping claim is made.

## Final validation — 2026-10-24

The redesign is **VALIDATED, not SHIPPED**. Fresh independent `worker-verify` returned overall PASS for all five criteria. The accepted plan above remains the scope baseline; its initial TASKED status and pre-implementation note are historical.

Memory Map is an enlarged, no-scroll viewport with no Index sidebar in map mode, a Map/Index toggle, and a contextual inspector beside the broad desktop map and stacked on mobile. Network/Neighborhood modes and filters remain available. Named Zoom in/out, Fit map, and Focus selected controls work; selection begins centered at natural scale. Background drag pans without moving nodes, Fit bounds the graph, and selection synchronizes across map, Index, and relationship rows. Labels/disclosures and the inspector expose readable memory details and typed directed relationships. The deterministic layout, keyboard roving focus and Enter/Space selection, global read-only behavior, project relationship editor, privacy rules, and API/data contracts remain intact.

Wheel zoom uses one native `{ passive: false }` listener attached only to the map viewport; it prevents page scrolling over the map and is cleaned up, while wheel input outside the map continues normal page scrolling. No global wheel blocker was added. The original reproduction and React delegated passive-listener root cause remain in the known-issue history.

Primary gates passed: focused layout/component tests 20/20; `npm test` 621/621 (0 failures; nonfatal Vite WebSocket port-in-use warnings only); `npm run build` (Vite passed and synced canonical source to CLI); `npm run check-cli`; pre-record `npm run specs:validate` (223 Markdown files, 87 feature specs, 39 ADRs, 246 local links); and `git diff --check`.

Independent verifier reran focused tests 20/20 and `npm test` 621/621, then independently verified all five criteria at 1440×900 and 375×812. Built-app Chromium evidence uses synthetic fixtures only (84 fake memory nodes, 26 fake typed edges; no real vault data). The report is `guarana-memory-map-pan-zoom-inspector.json`; screenshots are `guarana-memory-map-camera-1440.png`, `guarana-memory-map-camera-375.png`, `guarana-memory-map-selected-1440.png`, and `guarana-memory-map-selected-375.png`. The report and screenshots were temporary local synthetic-fixture evidence and are not included in the repository. Proof includes clipped/enlarged viewports, no horizontal overflow or programmatic map scrolling, fit/zoom/focus, cancelable wheel zoom without page/map scroll, normal outside-map scrolling, background pan with immovable nodes, readable labels/inspector/typed relationships, synchronized selection, filters and Neighborhood, keyboard and reduced-motion behavior, privacy boundaries, and no browser errors. No deployment or shipping occurred.
