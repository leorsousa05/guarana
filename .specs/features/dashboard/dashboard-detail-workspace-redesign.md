# Feature spec: Dashboard detail workspace redesign

**Status: SHIPPED**

## Goal
Redesign the unchanged Dashboard detail routes and Knowledge Home as distinct working views while preserving established capabilities, routes, contracts, security, privacy, and the Fieldstation shell.

## Requirements
- Redesign Activity (#/now), Runs (#/runs), Specs + Documents (#/specs), Workflow (#/workflow), Memory (#/memory), Skills (#/skills), and Models inside Settings, plus Knowledge Home (#/knowledge). The seven detail surfaces need route-specific page hierarchy and interactions, not merely navigation changes.
- Preserve Activity active workers, session tree, events, Advisor history, and injection detail; Runs project filter, 25-row pagination, and event modal; Specs overview/documents tabs, tracker, project state, pending-decision accept/reject, and Docs reader; Workflow phase map, history, task details, and parallel subtasks; Memory separate Project knowledge and read-only Global preferences, nested tabs, search, graphs, drafts, and injections; Skills Global/Project scope, search, and read modal; Models Primary/Advisor, source labels, catalog, manual IDs, variants, and save behavior.
- Make Knowledge Home a useful read-only working view rather than a duplicate sidebar directory. Aggregate only existing read endpoints for selected-project Specs tracker/pending decisions/docs tree, project Memory summary, unscoped read-only Global preferences, and Global/Project Skills. Keep cross-source search submitted/on-demand; do not crawl all Markdown bodies.
- Use useProjectFetch for project requests and opaque selected-project IDs. Global preference requests remain unscoped and read-only; do not add global mutation.
- Preserve all eight exact legacy hashes (overview, now, runs, specs, workflow, memory, skills, settings) and existing saved start-page precedence/behavior. Keep Settings Automation and Dashboard preference panels functionally unchanged.
- Preserve Fieldstation identity/tokens and do not change the shared shell or Sidebar. Preserve current local-only/server project-root allowlist security, project/global separation, privacy, route/API/settings contracts, and storage/schema behavior. Add no API/server/schema/storage mechanism or external dependency.
- Keep these supplied VALIDATED records unchanged as history: activity-redesign-phase-2b.md, runs-redesign-slice.md, specs-page-visual-redesign.md, memory-screen-redesign.md, skills-redesign.md, models-settings-density-redesign.md, page-flow-rework.md, and fieldstation-visual-identity.md. This is a distinct follow-up and does not alter their historical status.
- Budgets follow ADR-005 defaults: main thread at most 8k steady-state tokens; worker-code 8k, worker-verify 4k, and worker-debug 6k per dispatch; per-run hard cap 32k tokens and 15 minutes.

## Assumptions and scope
- Recompose all seven detail surfaces for clearer primary tasks, responsive density, and direct contextual detail while preserving every recorded behavior; Models is included, while Workflow preferences and Dashboard preference panels remain functionally unchanged.
- Knowledge Home uses search-first organization and truthful read-only at-a-glance decision, document/tracker, Project Memory, separately labeled Global preference, and Skills data; contextual links may target actual records or counts but must not recreate a sidebar directory.
- Reuse the Fieldstation palette, typography, and shell; distinguish layouts by each page's data and jobs rather than applying one generic card template.
- Route-specific page hierarchy and interactions for the seven listed detail surfaces and Knowledge Home.
- Preservation of existing actions, content, exact legacy routes, saved start-page behavior, selected-project and Global data boundaries, settings sources/inheritance, privacy, and local API contracts.
- Out of scope: shared shell/Sidebar redesign; changes to Settings Automation or Dashboard preference behavior; server/API/schema/storage/data/privacy/security/settings-contract changes; external dependencies; commit, push, deployment, release, or shipping.
- This planning handoff was superseded by the implementation and final verification record below; the earlier validated records listed above remain unchanged.

## Acceptance criteria
1. Knowledge Home does not render a duplicate directory/list of Specs, Memory, and Skills destinations. With synthetic non-empty responses it shows submitted cross-source search and read-only pending decisions, Specs document availability/tracker status, Project Memory counts, separately labeled Global preference counts, and Global/Project Skills data; source and Project/Global scope are explicit. It fabricates no recency or metrics. Empty, loading, and error states are truthful and independent. Selected-project calls carry opaque projectId; Global preference reads are unscoped and read-only. No global mutation, new endpoint/storage mechanism, or full Markdown corpus read is added.
2. Activity, Runs, Specs/Documents, Workflow, Memory, Skills, and Models each have a materially distinct route-specific page hierarchy and interaction presentation beyond shell, navigation, or heading-only changes. Rendered DOM, browser checks, or screenshots evidence each route redesign. All established content, controls, actions, and behaviors listed in this spec and the existing feature records remain available.
3. All eight exact legacy routes (overview, now, runs, specs, workflow, memory, skills, settings) and saved start-page precedence/behavior remain functional. Route-specific actions use existing local endpoints and settings source/project contracts. Settings Automation and Dashboard preference panels remain intact.
4. At 1440x900 and 375x812 all updated screens are usable without page-level horizontal overflow. Route-critical interactions work by keyboard and touch; visible focus, ARIA semantics, reduced motion, and truthful loading/error/empty states remain. Search, tab, list/detail, modal, row, and action-control semantics are tested where applicable.
5. No server/API/schema/storage/data/privacy/security/settings-contract change occurs. Focused tests, full npm test, production Dashboard build plus CLI sync, npm run check-cli, npm run specs:validate, git diff --check, and fresh independent synthetic-browser verification pass. No real project/Global content or external service is used.
