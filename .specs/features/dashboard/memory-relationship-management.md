# Feature spec: Guarana dashboard Memory relationship management

**Status: VALIDATED**

## Goal
Redesign the entire Guarana Memory dashboard experience and make relationships easier to inspect and manage.

## Requirements
- Redesign Injected, Summary, Search, and Graph as one consistent Memory experience while retaining their core behaviors and four accessible tabs.
- Retain Injected as the default tab, correct hydration and privacy behavior, Summary project/global counts, confirmed project-only Search and its result fields, and confirmed project/global graph nodes and typed edges with collision-safe scope identity.
- Make graph nodes readable and filterable by scope, relation type, and text; expose the selected memory's typed directed neighbors and lineage; preserve keyboard and pointer use, manual layout persistence and reset, and contained scrolling.
- Allow creation and exact-relation removal only for project memories. Validate project endpoints, existing confirmed nodes, and the typed relation enum (`caused-by`, `depends-on`, `supersedes`, `summarizes`, `fixes`, `relates-to`); reject invalid, self, duplicate, global, or cross-scope links. Require deliberate confirmation before removal.
- Offer local-only relationship proposals using confirmed project-memory TF-IDF search. Exclude the selected node and existing relations; display candidate score and rationale; require a human-selected relation type and explicit confirmation before any write.
- Keep global memories and edges visible and read-only through this project dashboard. Do not copy memory text or prompts to telemetry or send global content to external services.
- Preserve the paper/ink/ledger visual identity, semantic accessibility and visible focus, reduced-motion behavior, contained scrolling, and usability at 375px and desktop widths.
- Add focused UI, API, and engine tests for new behavior and preserve existing contracts. Run focused tests, npm test, dashboard build and sync, npm run check-cli, specs validation, git diff --check, and responsive/accessibility checks before independent verification.

## Assumptions and scope
- Keep the four existing tabs and established visual system while reorganizing hierarchy.
- The similarity engine proposes candidate nodes, not relation meaning; a person selects the typed relation.
- Use the existing local TF-IDF confirmed project-memory search as the initial suggestion source; suggestions are project-only and use no external model or network service.
- The full Memory area: Injected, Summary, Search, and Graph, including focused UI, API, and engine tests for project relationship editing and proposals.
- Preserve graph selection, neighbor and lineage navigation, keyboard and pointer interaction, and manual layout persistence/reset unless an implementation issue requires a documented replacement.
- No schema migration, external integration, AI auto-write, project-global relation, global mutation, dashboard draft/review UI, commit, or push.

## Acceptance criteria
1. The four Memory flows retain their core contracts: Injected remains the default with correct hydration and reference-only privacy; Summary reports both scopes; Search remains confirmed project-only with its type and result fields; Graph shows confirmed project and global nodes and typed edges with scope-qualified identity. The four ARIA tab relationships and ArrowLeft, ArrowRight, Home, and End navigation work.
2. Graph renders readable memory summaries and filters by scope, relation type, and text. Selecting a memory makes its typed directed neighbors and lineage inspectable. Keyboard and pointer interaction, manual layout persistence and reset, and contained graph scrolling work at 375px and desktop width.
3. Project relationship routes accept only `caused-by`, `depends-on`, `supersedes`, `summarizes`, `fixes`, or `relates-to` between existing confirmed project nodes and reject invalid endpoints, unconfirmed or missing nodes, invalid types, self-links, duplicate links, global endpoints, and cross-scope links. Removal targets only the selected exact relation and requires deliberate user confirmation. Global memories and edges remain unmodifiable through the added routes.
4. Relationship proposals come only from local confirmed project TF-IDF search, exclude the selected node and existing relations, and expose candidate score and rationale. No proposal writes automatically; a write occurs only after the user selects a relation type and explicitly confirms. No external model/service is called and memory text is not emitted to telemetry.
5. Focused UI, API, and engine tests cover the new behaviors and prior contracts. Focused tests, npm test, dashboard build and sync, npm run check-cli, specs validation, git diff --check, and responsive/accessibility checks pass; independent verification is recorded separately before status advances.
